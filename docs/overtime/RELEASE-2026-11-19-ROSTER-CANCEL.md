# 業務假日或臨時加班｜人員管理與已核准取消｜2026-11-19

## 已發布
- Supabase `overtime-management` v2：獨立管理 API，供已登入管理員新增、停用及重新驗證人員；主管可查看已核准與取消清單；員工持原申請憑證可請求取消。
- Supabase `overtime-sheet-bridge` v8：來源表核對、待驗證名冊處理、已核准取消完成回報；保留原核准、駁回流程。
- Supabase `overtime-requests` v14：完成取消後允許同人同日重新申請；原核准與駁回仍有效。
- GitHub Pages `overtime/management-ui.js` V1.2.0：員工、主管、管理員三個網站的操作入口。
- Google 月檢視 A5：排除狀態「已取消」，保留原「已駁回」排除條件。
- Google Apps Script V1.9.4 原始碼：支援人員自動驗證、取消核准工時安全清除、通知簽章與每分鐘備援。

## 安全閘門
- `overtime_sheet_bridge_keys.roster_ready` 與 `cancellation_ready` 預設為 `false`。
- 正式 Google Apps Script 還沒更新前，新員工留在待驗證狀態，不能直接申請；主管不准執行已核准工時取消。
- 更新私人 Apps Script 並執行含 `capabilities` 的 V1.9.4 後，Google 同步端會使用原有 Bridge Token 註冊能力與最後心跳，才會開放功能。
- 有效同步器超過 30 分鐘未回報，已核准取消功能重新鎖定。
- 取消採人工主管確認，Google 核對原時數與 Note；同一 Google batchUpdate 精準清除原工時格並將來源 P 欄標記「已取消」，讀回正確才回報資料庫。
- 不刪除原核准、主管姓名、原申請及歷史稽核。

## 尚未通過驗收
1. 私人 Apps Script 實際專案仍須取代原 `業務加班同步.gs`、儲存、更新現有網頁部署，等待能力心跳變成 true；不能靠單純更新 GitHub 當成部署。
2. 使用主管真實登入測試新 UI 與權限、實際員工新增及驗證。
3. 使用經核准的測試申請驗證完整取消，確認 Google 工時格清除、來源標記、月檢視移除及 Supabase「已取消」。
4. 新月份建表時仍須確認 E4/E5 正式月表以及主檔已包含新進人員；本功能不擅自插入正式人員列。

## 回復方式
- 網站前端：移除三個 HTML 中 `management-ui.js?v=1.2.0` 腳本引用即可暫時隱藏新介面。
- 取消功能：將資料庫同步器 `cancellation_ready=false`，保留既有工單，不直接改動任何已核准資料。
- 人員新增：將資料庫同步器 `roster_ready=false`，新進人員無法自動啟用；原有啟用名冊仍可使用。
- Apps Script：更新之前先保留舊版；若出現異常，重新部署舊版並恢復每分鐘觸發器。
